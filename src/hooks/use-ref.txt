**React useRef Hook - Notes**

### 1. **What is useRef?**
- `useRef` is a React Hook that allows you to persist a **mutable reference** across renders without causing re-renders.
- It is commonly used for:
  - Accessing **DOM elements**
  - Persisting values **without causing re-renders**
  - Storing **previous state values**

---

### 2. **Basic Syntax**
```jsx
const refVariable = useRef(initialValue);
```

---

### 3. **Common Use Cases**

#### **A. Accessing DOM Elements**
```jsx
import { useRef, useEffect } from "react";

const MyComponent = () => {
  const myRef = useRef(null);

  useEffect(() => {
    console.log(myRef.current); // Access the DOM element
  }, []);

  return <div ref={myRef}>Hello, useRef!</div>;
};
```
- `useRef` stores a **reference** to a DOM element, making it possible to manipulate it directly.

#### **B. Persisting Values Without Re-renders**
```jsx
import { useRef } from "react";

const Counter = () => {
  const countRef = useRef(0);

  const increment = () => {
    countRef.current += 1;
    console.log("Ref Value:", countRef.current);
  };

  return (
    <div>
      <button onClick={increment}>Increment Ref</button>
    </div>
  );
};
```
- Unlike `useState`, updating `useRef` **does not cause re-renders**.

#### **C. Storing Previous State Values**
```jsx
import { useRef, useEffect, useState } from "react";

const PreviousState = () => {
  const [count, setCount] = useState(0);
  const prevCountRef = useRef(0);

  useEffect(() => {
    prevCountRef.current = count;
  }, [count]);

  return (
    <div>
      <p>Current Count: {count}</p>
      <p>Previous Count: {prevCountRef.current}</p>
      <button onClick={() => setCount(count + 1)}>Increment</button>
    </div>
  );
};
```
- Stores the **previous state value** without triggering a re-render.

#### **D. Storing Timeout/Interval IDs**
```jsx
import { useRef, useState } from "react";

const Timer = () => {
  const timerRef = useRef(null);
  const [count, setCount] = useState(0);

  const startTimer = () => {
    timerRef.current = setInterval(() => {
      setCount((prev) => prev + 1);
    }, 1000);
  };

  const stopTimer = () => {
    clearInterval(timerRef.current);
  };

  return (
    <div>
      <p>Timer: {count}</p>
      <button onClick={startTimer}>Start</button>
      <button onClick={stopTimer}>Stop</button>
    </div>
  );
};
```
- `useRef` stores the **interval ID**, allowing it to persist between renders.

#### **E. Skipping useEffect on First Render**
```jsx
import { useEffect, useRef, useState } from "react";

const SkipFirstEffect = () => {
  const [count, setCount] = useState(0);
  const isFirstRender = useRef(true);

  useEffect(() => {
    if (isFirstRender.current) {
      isFirstRender.current = false;
      return;
    }
    console.log("Effect triggered!");
  }, [count]);

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>Increment</button>
    </div>
  );
};
```
- `useRef` is used to **skip the first render's effect execution**.

---

### 4. **Important Notes**
✅ `useRef` **does not trigger re-renders** like `useState` does.
✅ It is **useful for accessing and manipulating DOM elements**.
✅ Can persist values **without re-renders**.
✅ Use it to **store previous state values**.
✅ Useful for **skipping useEffect on the first render**.
✅ **Do NOT use `useRef` for UI state** updates. Use `useState` instead.

---

### **5. Wrong Usage Example (Avoid This)**
```jsx
const WrongExample = () => {
  const count = useRef(0);

  return (
    <div>
      <p>Count: {count.current}</p>
      <button onClick={() => count.current++}>Increment</button>
    </div>
  );
};
```
❌ The UI will **not update** when clicking the button because `useRef` changes do not trigger re-renders.

✅ Instead, use `useState` if you want UI updates.

```jsx
const CorrectExample = () => {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>Increment</button>
    </div>
  );
};
```
✔ This ensures the **UI updates** correctly.

---

### **6. Summary**
- `useRef` is great for **DOM access, storing values, tracking previous state, handling intervals, and skipping first renders**.
- **It does NOT cause re-renders** like `useState`.
- If you need to **update UI state**, always use `useState` instead.
